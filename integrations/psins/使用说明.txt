INSmini R2B · 自主记录与 PSINS 导航固件 3.0.4

日常使用

1. 板子供电后先放稳约 5 秒，完成陀螺静止零偏校准。
   本版使用五秒波动统计及运动检查；校准未完成时会等待，不把移动数据强行当成静止。
2. 连接已保存的 Wi-Fi 后，用同一局域网的电脑或手机打开板子 IP。
   本次测试地址 http://192.168.8.231/ 。地址由路由器 DHCP 分配，可能变化；
   USB 串口会打印 HTTP 地址。连接配置保留在板子的 NVS 中。
3. 插有 TF 卡时，校准完成后自动建立新记录。不用打开网页，也不依赖网络。
   不格式化、不删除卡上旧文件。每次启动/校准/真实与模拟模式切换均另建记录。
4. 网页“TF 卡自主记录”显示正在写入的条数、字节数及错误；拔电前点击
   “停止 TF 记录”，等待显示“已停止”。随后可下载该段的三个文件。
   记录期间列表只显示当前段；停止后点击“刷新记录”可查看历史记录。
   全部文件下载均需先停止并等待保存完成，避免读卡与自主写入相互影响。
   点击文件链接后，由浏览器直接保存原文件；看到文件下载完成后，点击“恢复实时显示”。
   刷新 TF 列表或下载时，网页姿态暂不刷新，浏览器 CSV 采集会停止并保留已收数据。
5. GNSS 天线到手后，断电接好正确天线，再将天线放在室外开阔处。
   本板有源天线馈电约 3.3 V，使用 GPS L1 + 北斗 B1、IPEX1/U.FL 接头的相容天线。

Type-C 与电脑读卡

当前 Type-C 提供供电、烧录与 USB 串口通信，不会在 Windows 中出现 TF 卡盘符。
TF 卡由 ESP32 使用。下载方式为：在网页停止 TF 记录，等待“已停止”，选择该段，
下载 session.json、stream.inl、closed.json；或停止记录后断电取卡，用读卡器读取。
不要在记录过程中拔卡。USB U 盘模式需要另行开发存储访问切换，当前未启用。

本次 Windows Edge 阻止了原始记录下载，显示 ERR_BLOCKED_BY_CLIENT；浏览器保存不算通过。
无需改浏览器设置，可用配套电脑工具：双击交付包“取回TF记录.cmd”。
工具会正常结束当前段、下载并校验三个文件、转换 PSINS 数据，然后恢复自主记录；
文件在交付包 records/ 的日期目录中。需要电脑与板子处于同一局域网。
在已安装 Python 的电脑也可运行：
  python tools/pull_insmini.py http://192.168.8.231 records --stop-and-resume
指定旧记录时添加 --session <记录号>，模拟记录还须显式添加 --allow-simulation。

网页姿态与组合导航

未定位时三维模型采用六轴相对姿态，航向以静止校准为零点，会漂移。
GNSS 有效、PPS/UTC 锁定且完成初始方向设置后，运行 PSINS 15 状态松组合。
此时三维模型自动采用组合导航姿态；页面方向角为真北顺时针 0～360°。
API/记录的 pitch、roll、yaw 保持 PSINS 312 约定，yaw 为真北逆时针角。

六轴 IMU 静止时不能确定绝对航向。可以在网页展开初始方向设置：
- 已知传感器 Y 轴相对真北顺时针方向角时，输入这个角度；
- 或明确把传感器 Y 轴沿前进方向安装，选择直行航迹对准，直行达到 2 m/s，
  连续取得三个有效定位后初始化。倒行、侧滑、手持任意姿态不适用此选项。
可在停止 TF 记录后勾选“保存到板子”，设定下次上电沿用的初始方向。
保存仅适用于定位时仍保持相同朝向的安装；换安装方向时必须修改或清除。默认不凭空假定朝北。

导航坐标是 ENU（东、北、天），传感器 XYZ 默认定义为体坐标右、前、上。
实际安装和板子丝印方向须核对；离线导入可用 Cbs 调整传感器到体坐标的旋转。
当前 GNSS 天线到 IMU 的杆臂按零处理。较长间距/高速转动需测量杆臂并进一步适配。

时间同步

IMU DRDY 与 GNSS PPS 均用 ESP32 同一个单调微秒时钟打时间戳。
GGA/RMC 通过校验和、日期、状态、卫星数、HDOP 和相同 UTC 历元检查后配对 PPS。
连续三个 PPS/UTC 配对才标记锁定；短时缺脉冲进入保持，超过 10 秒不再给出有效 UTC。
GNSS/GGA 高度由海拔高加大地水准面差得到椭球高；缺少高度时不拿 0 米代替。
RMC 仅提供水平速度，滤波器不把未知垂直速度当成 0 米/秒观测。
导航将实际 IMU 间隔积分到 100 Hz，使用原版 PSINS AVP 历史处理最多 0.85 秒观测延迟。

重要的实测边界：软件采用报文对应最近前一 PPS 秒沿的关系；尚未获得室外定位实测时，
只能验证软件时间同步流程，不能确认真实 GNSS 历元相位、GPIO PPS 延迟或微秒级精度。
真实硬件时序需要室外定位后与模块报文和 PPS 实测核对。

失锁与数据质量

导航状态 0=等待初始化，1=融合更新，2=GNSS 中断后的惯性推算，3=过期/数据异常。
超过约 2.5 秒没有有效 GNSS 观测会标记推算；超过 10 秒标记过期。
有 IMU 漏采、量程超限、队列溢出、存储错误时，不能把该段当成连续导航数据。
位置突跳会被门限剔除，但这不是完整的工业级完整性监控。

TF 文件与 PSINS 导入

卡上目录 /INSmini/<启动号_随机号_REAL或SIM>/ ：
  session.json   固件、模式、坐标、静止零偏、格式等信息
  stream.inl     带逐条 CRC32 的 IMU/GNSS/PPS/原始 NMEA/导航记录
  closed.json    正常结束信息、字节数、条数、丢弃数、写入状态

单文件约 64 MiB 自动另开一段。卡满或写入失败会明确报告；不自动删除旧记录。
停止后网页最多列出 128 个历史目录，读取需要数秒；超过后可断电用读卡器整理。
本版使用 64 KB 内存队列吸收短时写卡停顿，停止时先排空队列再关闭文件。
缓冲容量有限；超过缓冲能力、突然断电或卡损坏仍可能使记录不完整。
约每秒刷新缓存。突然断电仍可能损失最近数据或影响 FAT 元数据；结束文件不是掉电保护。
缺少 closed.json、记录尾部不完整、校验失败、数据间断均会被严格导入工具拒绝。
卡上已有的 SIM 段是软件测试数据；未正常结束的早期调试段不要作为正式实验结果。

把同一段的三个文件放入一个电脑文件夹，使用附带 Python 工具：
网页下载会自动加相同的记录号前缀，导入器可直接识别，无需改文件名。
每个文件夹只放一段记录，避免把不同记录混用；卡上原始固定文件名同样支持。
  python tools/insmini_session.py <记录文件夹>
模拟记录须显式添加 --allow-simulation。

工具会生成 imu.csv、psins_imu.txt、psins_gps_pos.txt、navigation.csv、gnss.csv、
pps.csv、truth.csv（模拟参考）、raw.nmea、validation.json。
psins_imu.txt 为 [Δθx Δθy Δθz Δvx Δvy Δvz t]，rad、m/s、s，逐样本使用实测间隔。
psins_gps_pos.txt 为 [纬度rad 经度rad 椭球高m t秒]，使用 PPS 历元而不是串口到达时刻。
原始 GNSS 记录保留观测，可能包含被在线滤波器剔除的异常点；离线重算仍需质量控制。

在 MATLAB 或 GNU Octave 中将 psins/ 加入路径，然后：
  insmini_setup_psins('<解压后的 psins260705 路径>');
  [imu,gpsPos,avp,meta] = insmini_session_load('<记录文件夹>');
模拟记录的调用为 insmini_session_load('<记录文件夹>',true)。
imu 为原始角增量减去静止陀螺零偏后的数据；原始记录和未减零偏的 ASCII 文件均保留。
avp 为板上原版 PSINS 已计算的姿态/速度/位置；meta.navigationStatus 保存对应质量状态。
当前 Windows 没有 MATLAB，导入与 PSINS 数学接口用 GNU Octave/原版工具箱验证。

USB 调试命令（115200，命令后发送换行）

  s           查看状态
  LOG stop    结束 TF 记录
  LOG start   开始新段 TF 记录
  LOG stall   仅供验证：暂停记录消费 5 秒，IMU 继续采样；日常记录无需使用
  SIM route   运行明确标记的虚拟 IMU/NMEA/PPS 轨迹，不发射射频信号
  SIM stop    恢复真实传感器，放稳约 5 秒重新校准
  WIFI off    暂停板子 Wi-Fi，TF 记录继续
  WIFI on     用已保存配置重新联网

SIM route 包含串口观测延迟、GNSS/PPS 中断、校验错误、定位突跳和 PPS 时刻跳变。
模拟模式网页有明显提示，日志以 SIM 结尾；严格导入默认拒绝模拟数据。
SIM 模式不能代替天线、接收机、RF 走线与物理 PPS 引脚的真实测试。

现有硬件与尚缺条件

现有硬件可做：六轴测量、相对姿态、静止陀螺校准、Wi-Fi 网页、独立 TF 记录、
NMEA/PPS 软件同步、已知初始方向下的 SINS/GNSS 松组合、数据回放与 PSINS 离线分析。
这不是把整个研究工具箱的所有算法/仿真/外设功能变成了板上功能。

必须补齐的实测条件：正确 GNSS 天线、开阔天空、初始方向或相容的直行安装方式。
若要求静止绝对朝向，需要磁力计或双天线定向等外部参考；单天线六轴不能实现。
若要求 RTK/原始伪距载波紧组合，需要相应 GNSS 接收机；本板 ATGM336H NMEA 不具备。
里程计、气压高度、视觉、星敏等对应 PSINS 示例需要相应外部传感器。
当前只做静止陀螺零偏校准，未完成六位置加速度计、温漂、杆臂和室外跑动标定。
低成本 MEMS 失去 GNSS 后位置会较快漂移，不宜作为已验证的高精度独立惯导。

离线窗外测试（2026-10-29）

本次用户同意固定朝向，准备使用保存的 manual 0°。摆放要求：
元件面朝上（ESP32 金属罩和芯片朝天），Type-C 所在的一边朝南，
GNSS 天线座所在的一边朝真北，即芯片 +Y 朝北、+X 朝东、+Z 朝天。
保持此朝向直到首次有效定位和组合导航初始化；本次建议全程固定，不拿着转动。
如用手机罗盘找北，请读取真北，并先远离天线磁铁、充电宝和金属件读方向。
近似对北用于功能验证，不能当成导航精度标定。

1. 先保持断电，接好天线和 TF 卡。拿到窗外或室外无遮挡处，先摆好上述朝向。
2. 摆好后再接移动电源供电；不要按住 BOOT 上电。上电后保持固定静止约 15 秒，以红灯慢闪为记录开始的准确信号。连续静止校准本身需约 5 秒。
   没有 Wi-Fi 或电脑也会保存 IMU、原始 NMEA 搜星信息、有效定位、PPS 和导航结果。
3. 天线接收面朝天；磁吸外壳款的塑料顶面朝上、磁铁底面向下。建议持续静置 10 分钟。不要先开机后一路转动搬运，以免途中已经初始化。
   板子也保持上述朝向，避免天线电缆拉扯接头；窗玻璃、遮挡和环境会影响接收。
4. 结束时在正常运行状态长按 BOOT 两秒，再松开；等待红灯常亮。
   常亮只在卡已正常结束记录、缓存排空且无写卡错误时出现，随后才能断电取卡。
   快闪可能是启动、正在保存、缺卡或错误；不能把快闪当成已经保存。
5. 回来最好保持同一移动电源供电，恢复 Wi-Fi 后让我取回这段记录。
   也可以常亮后断电，取出 TF 卡放读卡器；把整个 INSmini 文件夹复制到电脑后分析。
   中间重新上电会产生新的启动号，不能只取返程后的“当前段”。
   64 MiB 自动分段不等于一次试验结束，相关全部段都要保留。

分析工具：
  python tools/analyze_insmini_field.py <单段或INSmini文件夹> --output <电脑上的新报告目录>
工具分别核对：看见过卫星/载噪比、有效定位、PPS 与软件 UTC 锁定、
PSINS 实际导航记录、CRC/漏采/超量程/是否正常结束。不会只凭“ANTENNA OK”判定接收成功。
未正常结束的完整 CRC 前缀可用于诊断，但不会被冒充完整连续导航数据。
SIM 测试段默认排除；不会自动修补、删除或改写 TF 卡源数据。

保存离线初始方向的 API（仅设置流程使用）：
先停止记录并等待完全关闭，再 POST /api/navigation?mode=manual&heading=0&persist=1。
清除用 POST /api/navigation?mode=clear&persist=1，同样须先停止记录。
所有方向设置都需先停止并排空 TF 记录；未加 persist 的设置仅影响当前启动。
本次固定朝北测试请先在窗外摆好方向，再给板子上电并静置，避免途中先初始化后又转向。
